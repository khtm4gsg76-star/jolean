# مزاجي 2026 — منصة إدارة استضافة البوتات والمواقع

هذه المنصة ترفع مشاريع المستخدمين، تتعرّف على نوع المشروع، تجهّز بيئة التشغيل، تثبّت المتطلبات المتاحة تلقائياً، ثم تشغّل المشروع وتعرض سجلاته. وهي تدعم **البوتات والمواقع**؛ وليست مخصّصة لبايثون وحده.

> **مهم:** تجهيز المكتبات لا يعني إصلاح منطق كود المستخدم. عند وجود خطأ في الكود أو إعداد ناقص أو خدمة خارجية متوقفة، تسجّل المنصة الخطأ وتعرضه بدلاً من الادعاء بأن المشروع يعمل.

## 1. أنواع المشاريع

| النوع | ما الذي تفعله المنصة؟ |
|---|---|
| Python Bots | تنشئ بيئة افتراضية مستقلة لكل مشروع، وتقرأ `requirements.txt` أو تستنتج المكتبات الخارجية من أوامر الاستيراد، ثم تثبّت المكتبات وتشغّل ملف الدخول. |
| Python Websites | تتعرّف على تطبيقات Flask وFastAPI وDjango الشائعة، وتستخدم منفذ المشروع وعنوان `0.0.0.0` عند تشغيلها بالطريقة المدعومة. |
| Node.js Bots | تثبّت اعتماديات npm أو pnpm أو Yarn عند وجود ملفات القفل، ثم تنفّذ أمر `start` أو ملف الدخول. |
| Node.js Websites | تشغّل أوامر البدء المدعومة، أو تنفّذ `build` وتقدّم ناتج الموقع من `dist` أو `build` أو `out` أو `public` عند وجود صفحة HTML رئيسية. |
| PHP Bots | تشغّل ملفات PHP عبر CLI، وتنفّذ تثبيت Composer عند وجود `composer.json`. |
| PHP Websites | تشغّل خادم PHP المدمج مع موجه داخلي لدعم `index.php` ومسارات المواقع، وتدعم ملفات HTML مع نقاط PHP عند وجودها في المشروع. |
| Static Websites | تقدّم `HTML/CSS/JavaScript` والصور والملفات الثابتة عبر خادم HTTP، مع دعم SPA fallback عند طلب مسارات صفحات غير موجودة. |

تتضمن صورة Docker أدوات Python وNode.js وPHP وComposer. لكن المكتبات التي تعتمد على برامج نظام إضافية أو قواعد بيانات أو متصفحات أو خدمات خارجية قد تحتاج متطلبات خاصة بالمشروع.

## 2. طريقة الرفع والتشغيل

1. لرفع بوت أو موقع متعدد الملفات، اضغط المشروع بصيغة ZIP أو TAR أو TAR.GZ أو TGZ أو TAR.BZ2 أو TAR.XZ وارفعه من زر الرفع التلقائي.
2. ضع ملفات المشروع داخل الأرشيف. يفضّل أن يحتوي مجلد الموقع على `index.html` أو `index.php`، وأن يحتوي مشروع Node على `package.json` وملفات القفل إن وجدت.
3. بعد الرفع، يفك النظام الأرشيف بعد التحقق من المسارات والروابط الرمزية، ويكتشف نوع المشروع وملف الدخول.
4. يجهّز بيئة المشروع ويثبت الاعتماديات. لا يعيد تثبيت Node أو Composer دون تغيّر ملفات الاعتماديات، ولا يعيد بناء مشاريع Node إذا لم تتغير ملفات المصدر التي تدخل في البصمة.
5. يبدأ التشغيل في الخلفية. المواقع لا تُسجّل كـ Running إلا بعد نجاح فحص الاستماع على المنفذ.
6. راجع `out.log` و`errors.log` عند فشل التثبيت أو التشغيل.

يمكن رفع ملف بداية منفرد مثل `.py` أو `.js` أو `.mjs` أو `.cjs` أو `.ts` أو `.tsx` أو `.php` أو `.html` أو `.htm`. أما المواقع متعددة الملفات فتُرفع داخل أحد الأرشيفات المدعومة أو تُرفع ملفاتها عبر مدير الملفات.

## 3. ملفات اعتماديات المشاريع

- **Python:** أرفق `requirements.txt` عند الإمكان. الاكتشاف التلقائي يستنتج أسماء الحزم من `import` الشائع، لكنه لا يستطيع معرفة الاستيرادات الديناميكية أو المكتبات المحمّلة بأسماء مخفية أو كل متطلبات النظام.
- **Node.js:** يفضّل إرفاق `package-lock.json` أو `pnpm-lock.yaml` أو `yarn.lock`. تستخدم المنصة ملف القفل لتثبيت متكرر قابل للتوقع، وتفحص اكتمال حزم npm المخزنة مؤقتاً.
- **PHP:** أرفق `composer.json` ويفضّل `composer.lock`. تثبّت المنصة اعتماديات Composer عند توفر Composer.
- لا تضع أسرار لوحة تحكم مزاجي في `.env` الخاص بالمشروع. يمكن للمشروع استخدام متغيراته الخاصة، لكن متغيرات النظام الحساسة والمنافذ المحجوزة للمنصة لا يمكن استبدالها بملف `.env` المرفوع.

## 4. إدارة التشغيل

تدعم لوحة التحكم التشغيل والإيقاف وإعادة التشغيل ومشاهدة السجلات، مع مراقبة العمليات ومحاولات استعادة محدودة للمشاريع التي تتوقف فجأة. إذا تكررت أعطال المشروع، تتوقف محاولات الاستعادة بعد الحد المقرر وتتحول الحالة إلى خطأ حتى لا يدخل في حلقة تشغيل لا نهائية.

إعادة التشغيل لا تعني إعادة كتابة كود المشروع. المنصة لا تستطيع تلقائياً إصلاح أخطاء منطقية مثل استدعاء API خاطئ أو توكن منتهي أو قاعدة بيانات غير متاحة.

## 5. إعداد Railway

1. ارفع **محتويات هذا المجلد** إلى جذر المستودع، بحيث يكون `Dockerfile` و`app.py` في الجذر نفسه.
2. اختر Dockerfile كطريقة بناء عند الحاجة، واستخدم إعداد التشغيل الموجود في `Dockerfile` أو `Procfile`.
3. أنشئ Volume دائم واربطه بالمسار `/data`.
4. أضف المتغيرات السرية من Variables ولا تضعها داخل الملفات أو المستودع:
   - `SECRET_KEY`: مفتاح عشوائي طويل وثابت.
   - `ADMIN_PASSWORD`: كلمة مرور المسؤول عند إنشاء قاعدة بيانات جديدة؛ لا يعاد تعيين حساب المسؤول الموجود تلقائياً عند كل تشغيل.
   - `BOT_TOKEN`: توكن بوت إدارة مزاجي إذا كان مستخدماً.
   - `TELEGRAM_WEBHOOK_SECRET`: سر Webhook إذا كان Webhook مستخدماً.
   - `API_BASE_URL`: رابط لوحة مزاجي العام عند استخدام بوت الإدارة الخارجي.
   - `ADMIN_TELEGRAM_IDS` و`ADMIN_TELEGRAM_ID`: معرفات الإدارة بحسب مسارات التكامل المستخدمة.
5. تأكد من `MAZAGI_DATA_DIR=/data`، ثم انشر وانتظر نجاح فحص `/healthz`.

## 6. إعداد Render

ملف `render.yaml` يستخدم Docker وقرصاً دائماً بمسار `/data` وحجم ابتدائي 1 GB. القرص الدائم يعتمد على نوع الخطة المتاحة لدى Render وقد يتطلب خطة مدفوعة. راجع مساحة القرص ووسّعها بما يناسب المستخدمين؛ لا تحذف القرص أو تنفّذ مسحاً للبيانات إذا كان يحتوي ملفات فعلية.

## 7. الملفات والبيانات الدائمة

- قاعدة البيانات: `/data/db.json`.
- ملفات المستخدمين ومشاريعهم: تحت `/data/USERS/`.
- بيانات النسخ الاحتياطية: `/data/backups/`.
- لا ينبغي تخزين قاعدة البيانات الحية داخل مجلد التطبيق أو مجلد الملفات العامة.
- عند اكتشاف قاعدة بيانات غير صالحة، يجب أن يتوقف البرنامج برسالة واضحة بدلاً من الكتابة فوقها بقاعدة فارغة.
- خذ نسخة احتياطية خارج Volume بشكل دوري. وجود Volume وحده لا يغني عن النسخ الاحتياطي.

## 8. الحماية وحدود الاستخدام — اقرأ قبل فتح التسجيل للعامة

**هذه النسخة ليست بيئة تنفيذ متعددة المستأجرين معزولة بالكامل.** عمليات المستخدمين لا تزال تعمل كعمليات فرعية داخل حاوية/مضيف الخدمة نفسه وبمستخدم نظام التشغيل نفسه. بيئة Python المنفصلة وتصفية متغيرات البيئة تقللان تداخل الاعتماديات وتسريب أسرار لوحة التحكم، لكنهما لا تمنعان مشروعاً خبيثاً من محاولة الوصول إلى ملفات أو عمليات مستخدمين آخرين داخل المضيف. لا تفتح رفع الكود للعامة ولا تشغّل ملفات من مصادر غير موثوقة قبل إضافة عامل تشغيل معزول لكل مشروع (حاويات مستقلة وصلاحيات مقيدة وقيود موارد فعلية).

- حقول RAM وCPU في الخطط لا تتحول وحدها إلى حدود نظام تشغيل مفروضة؛ تحتاج cgroups أو حاويات مستقلة.
- حد التخزين يطبّق عند الرفع وبعد تثبيت الاعتماديات، لكن زيادة السجلات أو الملفات أثناء تشغيل المشروع تحتاج مراقبة دورية وحدوداً على مستوى القرص.
- وكيل ASGI يمرّر HTTP وWebSocket للمواقع. هذا لا يعني دعم TCP الخام أو أي منفذ إضافي غير منفذ HTTP المخصص للمشروع.
- يجب أن يستمع خادم الموقع على `0.0.0.0` ويستخدم متغير `PORT` الذي تزوده المنصة. المشاريع التي تثبت منفذاً آخر أو تتطلب أكثر من منفذ تحتاج إعداداً مخصصاً.
- أدوات النظام الإضافية غير المضمّنة في Dockerfile لا تُثبت تلقائياً لمجرد وجود `import` أو حزمة في المشروع.
- لا ترفع مفاتيح API أو توكنات Telegram ضمن أرشيف عام. استخدم متغيرات بيئة المشروع، وألغِ أي توكن سبق كشفه في أرشيف أو مستودع.

## 9. فحص سريع قبل النشر

```bash
python -m py_compile app.py telegram_bot.py telegram_bot_runner.py mazaji_static_site_server.py
php -l mazaji_php_site_router.php
```

يجب أيضاً إجراء اختبار نشر حي على حساب Railway أو Render باستخدام حساب تجريبي: ارفع بوتاً تجريبياً وموقعاً ثابتاً وموقع PHP ومشروع Node، ثم أعد تشغيل خدمة المنصة وتأكد من استمرار البيانات والملفات على Volume. نجاح الفحوصات المحلية لا يثبت وحده نجاح النشر أو توافق كل مشروع مرفوع.


## دعم المواقع العامة والتقنيات

تستقبل المنصة مشاريع ZIP وTAR وTAR.GZ وTGZ وTAR.BZ2 وTBZ2 وTAR.XZ وTXZ. لا تدعم هذه النسخة RAR أو 7z تلقائياً؛ فكّها محلياً ثم أعد ضغط المشروع بإحدى الصيغ المدعومة. يجري فك الأرشيف بفحص المسارات والروابط الرمزية وعدد الملفات والحجم الفعلي بعد الاستخراج.

التشغيل التلقائي الحالي موجّه إلى التقنيات الشائعة التالية: مواقع HTML/CSS/JavaScript الثابتة، PHP وComposer، Node.js مع npm/Yarn/pnpm عند وجود Corepack، وأطر الويب الشائعة في Node مثل Express وFastify وNext.js وNuxt وVite وAstro وAngular وVue وSvelte وRemix وNestJS، ومشاريع Python مثل Flask وFastAPI وDjango وStreamlit وGradio. بعض أطر Node التي تنتج ملفات static يتم تقديمها مباشرة من ناتج البناء مثل dist/build/out، بما في ذلك مجلد Angular browser المتداخل.

ليس من الممكن تشغيل كل لغة أو إطار في العالم بمجرد رفع الملف؛ أي مشروع يحتاج Runtime أو خدمة نظام أو قاعدة بيانات أو متغيرات API غير متوفرة يحتاج إعداداً خاصاً. لا تُعتبر امتدادات Java أو Go أو Ruby أو .NET مدعومة للتشغيل التلقائي في هذه النسخة.

### روابط المواقع على نطاقات فرعية

الافتراضي أن رابط الموقع يكون تحت `/public-site/<token>/` على نطاق لوحة مزاجي. لتحسين توافق المواقع التي تستخدم مسارات أصول مطلقة أو WebSocket، يمكن إعداد نطاق فرعي مستقل بمتحول البيئة `PUBLIC_SITE_DOMAIN` مثل `sites.example.com`. يجب أولاً إعداد DNS wildcard `*.sites.example.com` ليوجه إلى خدمة مزاجي وإصدار شهادة TLS تغطي النطاق الفرعي wildcard لدى مزود الاستضافة، ثم ضبط:

- `PUBLIC_SITE_DOMAIN=sites.example.com`
- `PUBLIC_SITE_SCHEME=https`
- اختيارياً `PUBLIC_BASE_URL=https://panel.example.com` للرابط الأساسي للوحة إذا كان مختلفاً.

ستُنشئ المنصة اسماً فرعياً عشوائياً منفصلاً لكل موقع. هذا الإعداد لا ينشئ DNS أو شهادة TLS تلقائياً؛ يجب إعدادها لدى مزود النطاق والاستضافة. في حال عدم ضبطه تبقى الروابط العامة بالمسار token-based.

يدعم وكيل ASGI تمرير WebSocket للمواقع عبر الروابط العامة ومسارات النطاقات الفرعية. يظل مطلوباً أن يستمع تطبيق المستخدم على `0.0.0.0` والمنفذ `PORT`، وأن تكون تقنية التطبيق نفسها مهيأة لدعم WebSocket.


## إصلاح تشغيل Railway تلقائياً (خطأ PORT)

لا يحتاج هذا الإصدار إلى إدخال Start Command يدوياً. ملف `railway.json` يطلب من Railway بناء `Dockerfile` واستخدام `python railway_start.py` تلقائياً في النشر الأساسي وبيئتي `production` و`pr`. يقرأ المشغّل قيمة `PORT` من بيئة النظام كعدد صحيح، ثم يشغّل ASGI على `0.0.0.0`.

ولمعالجة أمر Uvicorn القديم الذي قد يبقى محفوظاً في إعدادات خدمة Railway، تحتوي صورة Docker على طبقة توافق باسم `railway_uvicorn_compat.py`:
- إذا شغّل Railway `uvicorn ... --port ${PORT:-8080}` دون Shell، تستبدل الطبقة التعبير الحرفي بقيمة `PORT` الفعلية.
- إذا كان الأمر يستخدم `--port=$PORT`، تعالجه الطبقة أيضاً.
- لا تغيّر المنافذ الرقمية العادية.
- إذا تجاوز الأمر نقطة دخول Docker وشُغّل كـ root، تعيد الطبقة التشغيل عبر `docker-entrypoint.sh` لتطبيق صلاحيات `/data` وتشغيل الخدمة بحساب `mazagi` غير المميّز.

**مهم:** يجب أن يبني Railway صورة جديدة من ملفات هذا الإصدار. إعادة تشغيل Deployment قديم أو إعادة نشر نفس Commit القديم لن تُدخل طبقة التوافق الجديدة. عند استخدام GitHub، استبدل ملفات المشروع بهذه الحزمة وادفع التغييرات إلى الفرع المتصل بخدمة `web`؛ لا تكتب أي أمر في خانة Start Command ولا تغيّر متغير `PORT` يدوياً.
